Never Lose a Heartbeat: design note

hbpipe · code: github.com/Harsh202458/mayacardio-hbpipe · cloud: hbpipe-cloud.onrender.com · device evidence: ARM64 (linux/arm64 Debian 12 container, --cpus 4 --memory 2g)

  • Collector: one TCP client polls each sensor every 100 ms and always requests from_index = cursor, so restarts, duplicate and corrupt replies are harmless re-reads. The CRC-32 is checked on the exact data text received (never re-serialised JSON). Every line is applied by its own sensor and index range.
  • Writer thread: commits batches strictly in order, so a slow fsync (SD cards stall) never stops reading the mock's 10 s buffer.
  • Uploader: offline results first, then the newest 30 s (live lane), then the backlog oldest-first. Data counts as uploaded only after the cloud has committed and replied. Progress is kept as acknowledged chunk-id ranges, so stored rows are never rewritten.
  • Mode: health ping every 1 s on a kept-alive connection. Offline after ≥2 failures and 5 s without success; online after 2 successes (pings every 0.5 s while offline). systemd Restart=always, RestartSec=200ms; the collector starts before the cloud code even loads.
  • Processing: one module, used unchanged online and offline. Window w is computed only when all its inputs are final (data, recorded loss, or past session end), so samples in transit are never counted as missing. The cloud skips windows the device already processed offline.

2. Why no sample is lost silently

For every (session, sensor), the indices [0, cursor) are covered exactly once by stored blocks and recorded losses. Each block or loss is committed in the same transaction as its cursor advance, so this holds after any crash.

  • Uncommitted data is simply "not read yet": it is re-read after a restart while the mock still holds it.
  • Unexplained index jump: re-read; recorded as not_delivered_by_mock only after 5 failed re-reads.
  • New session_id: the old session's unread tail is listed with to_index: null, reason device_power_loss_or_reboot (boot id changed) or mock_restart.
  • Disk full: release a 16 MB reserve and keep saving; below 4 MB, store only disk_full loss records while still reading the mock; resume when space returns.
  • Exactly once in the cloud: immutable blocks keyed (session, sensor, first_index) plus ack-after-commit, so re-sends are no-ops.
  • Nothing is ever interpolated.

4. Maximum data loss on a power cut: 0.5 s per sensor

When power is cut, the mock dies too. What can be lost is what the mock had produced but we had not yet committed:

  • up to one poll interval (0.1 s);
  • plus one commit interval (0.2 s);
  • plus the fsync time.

That is ≈ 0.35 s; we state 0.5 s. Measured on the ARM64 device (whole container killed, mock included): 0.02–0.055 s per sensor over 2 cuts. These samples appear after reboot as the old session's tail loss (to_index: null). Committing more often lowers the bound at the cost of SD-card writes.

5. Results logic (section 3)

  • Windows: 400w…400w+399. Missing counts, per-channel mean/min/max over available samples (null if none); magnitude = mean √(ch1²+ch2²) of sensor 2.
  • Peaks: the 800 previous samples and the next one are available, strict local maximum, 2·x > max(previous 800), ≥100 after the previous peak (rolling max via a monotonic deque, O(n)).
  • Heart rate: 24000·(k−1)/(last−first) over the peaks in the 5 s span; null if w<4, any sample is missing, or <2 peaks. The chain is warmed up 2000 samples earlier, which matches the full-history chain (unit-tested).
  • Rounding: half away from zero, on exact rationals.
  • Check: the ECG mock gives 60/90/72 bpm exactly as scheduled.

8. Assumptions and notes

  • Official mock: the mock download link was blank in our copy. We implemented section 6 faithfully (tools/fake_mock.py) plus a ground-truth checker; the pipeline uses only the documented protocol.
  • Assumed: the peak chain carries across the session; stats fields are mean_1/min_1/max_1/… per-channel lists; windows processed offline are not recomputed online.
  • Free services only: Render free + Neon free, with no payment method on either. Everything else is open source.
